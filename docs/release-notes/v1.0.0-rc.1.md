The release candidate for Conductor 1.0. From 1.0 on, the promises in [STABILITY.md](../STABILITY.md) hold: every
later 1.x release opens your data and settings as they are, and the Subsonic API and Conductor's own extensions keep
every call and field (new ones may be added). This candidate is what 1.0 will be unless running it turns something up.

## New
- **Settings in Podium.** Every setting in the [settings reference](../CONFIG.md) can be changed from Podium ›
  Settings: grouped and described as there, with its default and current value. Keys and passwords go to
  `secrets.toml` and are never shown; a value Conductor can't use isn't saved; a restart uses the change. Music
  folders and the data folder stay with `conductor setup`.
- **"Made for you" without AudioMuse-AI** (`encore.forYou`): a mix from the artists you play most and those that go
  with them, about 60% new to you, the same all day and new each day. Encore 1.12 uses it on a server without
  AudioMuse-AI.
- **Linux packages** for Debian and Ubuntu (.deb), Fedora and openSUSE (.rpm) and Arch, x86-64 and ARM64. They bring a
  system service that runs as its own `conductor` user, not started until you set it up. Each package is installed and
  removed again in its own system on every change.
- **Conversions are cached and capped.** A load test found ffmpeg unbounded: 64 apps converting at once used every
  core and about 3 GB. Now a converted song is written to a cache while it's sent (ffmpeg is done in a second or two
  however slowly the app listens, and it's played again and seeked from the cache), `transcode_slots` ffmpegs run as
  a rule (half the cores), and ffmpeg runs at a lower priority than everything else. On a 2-slot test server, 8
  listeners starting together start in 0.7 s, and 64 apps never pass 8 ffmpegs.
- **The API's contract.** Every call's answer is recorded field by field ([docs/api/](../api/)), with a spec for each
  of Conductor's own extensions, checked by the tests and by CI on every change.

## Security
- **Every web page runs only its own script** (a Content-Security-Policy with the script's hash), so markup that got
  into a page some other way can't run.
- **Podium and setup** now also refuse to be shown inside another site's frame and aren't cached; Podium's cookie is
  `Secure` over HTTPS through a proxy on the server. Every answer says `nosniff`.
- Dependencies are checked against the RustSec advisories on every change (that's how 0.5.1's SQLite fix was found).

## Fixes
- **Podium on a phone:** the username box no longer capitalises its first letter (signing in failed); a wrong password
  says so; the open tab stays marked (also for screen readers); labels sit above their boxes.
- **Readable buttons in dark mode** in Podium and setup (white on light blue, 2.3:1, is now dark ink at about 8:1);
  boxes named only by a placeholder are named for screen readers too.

## Files
- Linux: `conductor-1.0.0-rc.1-linux-x86_64.tar.gz` and `-aarch64`, and the packages: `conductor_1.0.0.rc.1_amd64.deb`
  (and arm64), `conductor-1.0.0.rc.1-1.x86_64.rpm` (and aarch64), `conductor-1.0.0rc.1-1-x86_64.pkg.tar.zst` (and
  aarch64). Then `conductor setup`. The packages call themselves 1.0.0~rc.1 (Arch: 1.0.0rc.1), so 1.0.0 replaces them.
- Windows: `conductor-1.0.0-rc.1-windows-x86_64.zip` (`install.ps1` installs the service).
- `SHA256SUMS.txt`, and `docker pull ghcr.io/d-safro/conductor:1.0.0-rc.1`.

Upgrading from 0.5: replace the program, the package or the image; there's nothing to run.
