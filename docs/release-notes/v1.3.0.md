Conductor 1.3: the download requests as a public call (`encore.requests`), so tools and apps can show and manage what
Conductor is fetching without Podium's private API.

## New
- **`encore.requests`** ([spec](../api/encore.requests.md)): `getRequests` lists the songs asked for and Lidarr's
  albums, newest first, with their state (searching, queued, downloading with progress, done, not found, failed, set
  aside), why they were asked for (a heart, a playlist, a trial, a mix, a discovery, Lidarr), who asked, and what the
  caller may do with them; filters by state, type and user, and pages. An admin sees everything and can retry,
  cancel, set aside, search Soulseek for other files and pick one (`retryRequest`, `cancelRequest`,
  `setRequestAside`, `searchRequestFiles`, `pickRequestFile`); everyone else sees only their own requests. Podium
  uses the same code, so both always agree.
